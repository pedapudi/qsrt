# GLM-5.2 QSRT experiment journal and artifact index

## Purpose and status

This historical journal records the files, container images, commands, and
measurements used to test the Quantile-Stratified Rate-shifted Trellis codec
(QSRT) on GLM-5.2. It provides the provenance needed to reproduce the
experiments and to remove their artifacts safely.

Status at 2026-08-18: execution is active. No GLM-5.2 QSRT result in this
journal qualifies a checkpoint until a complete candidate passes the paired,
document-disjoint forward-KLD and serialized-byte gates defined below.

The experiment program evaluates three format-preserving changes:

1. score paths through the graph of legal reconstructions, called a trellis,
   with a two-sided model-loss curvature estimate;
2. fit values in the finite eight-bit E4M3 floating-point format after the
   matrix-aware BlockLDLQ feedback step; and
3. refit each down projection against activations rebuilt from its quantized
   gate and up projections.

The production-domain gate rejected reconstruction-table training on the
frozen layer-3 panel. The active implementation sequence therefore retains
curvature-scored path selection and reconstructed-activation down refitting.
Table training remains a research control unless another production domain
shows materially larger fixed-path E4M3 headroom.

The comparison checkpoint uses EXL3, a variable-rate trellis weight quantizer.
The first GLM-5.2 panel includes a matched encode with EXL3's multiplier-based
computed generator, identified by EXL3 as MCG. K3 identifies a three-bit
trellis payload per weight. The matched control separates a reconstruction-law
effect from differences in source tensors, transforms, calibration rows, or
covariance.

## Governing constraints

- The complete official BF16 GLM-5.2 checkpoint must not be downloaded.
- Existing EXL3 checkpoint files must not be downloaded again.
- Any container that mounts a model directory must disable network access and
  mount the model directory read-only. A result-only container may omit model
  mounts entirely.
- A bounded BF16 source window may contain only the source shards required by
  a frozen real-expert panel.
- Fit, selection, and reporting documents must be disjoint.
- Every checkpoint comparison must use identical non-expert tensors.
- Checkpoint size includes payloads, tables, scales, metadata, alignment, and
  padding.
- A smaller valid measurement may reject a change. A pass only authorizes the
  next measurement at a broader scope.
- The installed generic Gilded Gnosis container remains available. Runtime
  experiments use a separate digest-pinned EXL3 container.

## Acceptance criterion

A complete QSRT GLM-5.2 checkpoint qualifies only when both conditions hold:

- its serialized checkpoint occupies fewer bytes than the immutable EXL3
  comparison checkpoint; and
- its teacher-to-candidate forward Kullback-Leibler divergence (KLD) is lower
  on the same document-disjoint inputs.

Repeated evaluations of the same artifact pair must establish the uncertainty
of the paired KLD difference. Weight error, tile error, expert-output error,
and local curvature are screening measurements. They do not satisfy the
checkpoint acceptance criterion.

## Results

### Matched MCG and SQG K3 on eight complete real experts

The frozen layer-3 panel contains eight complete GLM-5.2 experts and 24
matrices. Every SQG encode had lower raw weight SSE than its matched MCG
encode. The pooled SQG-to-MCG SSE ratio was `0.9739509693`, which is a 2.6049%
reduction. The gate, up, and down reductions were 2.6139%, 2.6221%, and
2.5774%, respectively.

This result confirms the reconstruction-law direction on real BF16 weights
under the production transforms, scale search, BlockLDLQ feedback, Viterbi
path, and decoder. All eight experts come from one early layer. The result does
not measure routed expert outputs, downstream loss, or full-model KLD.

### Uniform K3 byte ledger for the frozen eight-expert panel

The dense-endpoint receipts record the logical trellis and scale bytes for
the same 24 projection matrices under the immutable EXL3 allocation and
uniform QSRT K3. EXL3's layer-shared scale storage is unchanged by replacing
only eight experts, so the comparison charges its expert-specific scales and
charges every QSRT scale plus the shared 4,096-byte reconstruction table.

| Component | EXL3 bytes | Uniform QSRT K3 bytes |
|---|---:|---:|
| Trellis payloads | 133,693,440 | 113,246,208 |
| Expert or matrix scales | 98,304 | 393,216 |
| Shared QSRT reconstruction table | 0 | 4,096 |
| Total charged logical bytes | 133,791,744 | 113,643,520 |

Uniform K3 saves 20,148,224 charged logical bytes across the eight experts.
The calculation comes from every per-projection receipt rather than nominal
bits per weight. It is not a serialized-checkpoint result: the GLM QSRT port
does not yet have a frozen container, headers, alignment, padding, or runtime
directory. The byte result proves that the candidate has enough logical-rate
margin for a smaller endpoint; it does not satisfy the complete-model size
gate by itself.

### Production values presented to the trellis encoder

The production diagnostic records the normalized 256-value tiles presented to
the dynamic-programming trellis search, called Viterbi search, after BlockLDLQ
feedback. It also records the error between each tile and the reconstruction
selected by the frozen E4M3 table.
The frozen layer-3 panel contains eight experts, three projections per expert,
and 24 complete matrices.

Every matrix used all 4,096 table entries. Table-index entropy ranged from
11.9947 to 11.9971 bits, close to the 12-bit maximum. Target excess kurtosis
ranged from -0.0013 to 0.0258, while residual excess kurtosis ranged from
-0.0304 to 0.0028. The largest absolute adjacent-value correlation was
0.00073 for targets and 0.00070 for residuals.

These measurements show nearly Gaussian marginal values, negligible adjacent
dependence, and broad table occupancy on the frozen panel. They provide little
support for training the table solely to match a non-Gaussian marginal or a
simple adjacent-value pattern. They do not measure the best per-entry centroid
for fixed paths, path changes after table updates, curvature-weighted loss, or
full-model KLD.

### Fixed-path reconstruction-table update

The fixed-path oracle fits one reconstruction value to every occupied table
entry while preserving the paths selected by the frozen table. The
unconstrained version stores each fitted value as a floating-point centroid.
The format-preserving version rounds each centroid to finite E4M3 and retains
the frozen value for any unused entry.

Across the 24 matrices, the unconstrained centroid update reduced pooled
fixed-path SSE by 0.0467%. Individual matrix reductions ranged from 0.0442% to
0.0504%. Finite-E4M3 centroids reduced pooled fixed-path SSE by 0.00175%, with
individual matrix reductions from 0.00144% to 0.00202%.

The oracle fits a separate table to each matrix using the same values that it
scores. A production shared table has less freedom and must also generalize to
unseen matrices. The finite-E4M3 result therefore provides no practical
motivation to implement table training on the measured domain. The result does
not bound a joint optimization that repeatedly reassigns paths, and it does
not measure KLD. Repeated path reassignment would need to overcome a negligible
first table-update step before it could affect the model-level objective.
